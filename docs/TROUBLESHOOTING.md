# 连接与会话排障

先保留现场，再定位失败层。不要静默结束 `pfclscom.exe`、关闭 Creo、启动第二个会话、反复加载同一路径 DLL，或换 DLL 名称绕过占用。确需重启或注册修改时，说明原因、受影响会话和未保存内容，按用户已有授权处理。

## 先核对后端失败处理

原始 `creo_client.py` 的 `connect()` 失败后会调用 `taskkill /F /IM pfclscom.exe`；外层 `_with_creo` 还可能重连并重复操作。这与旧技能的“不要杀通信进程”原则冲突。`creo_status`、`creo_diagnose`、`creo_native_status` 也会进入这些连接路径，不能作为绝对只读的试探工具。

本仓库不包含后端，不能修复使用者已安装的连接实现。首次连接前确认已采用不会静默清理进程的实现。未确认时，先只查看界面、系统进程与已有日志，不触发已知自动清理代码。发生一次 RPC/服务器故障后，停止重复和并发调用，保存错误与现场，待界面恢复或用户处理后再决定下一次尝试。

## 无连接检查

1. 确认可见 Creo 会话在运行，没有文件导入、未完成命令或模态框阻塞。
2. 查看 `parametric.exe`、`xtop.exe` 与对应窗口。一个启动器和一个主程序可能属于同一会话；不能仅看总进程数判断多开，更不能据此自动结束进程。
3. 核对 Creo 与 MCP 的用户、权限、版本、目标路径和 COM 注册可见性。
4. 查看 `<BRIDGE_ROOT>` 连接日志与 `<TOOLKIT_ROOT>` 插件日志；分享前去除用户名、个人路径、许可服务器地址和模型信息。

安全后端已确认、界面空闲时，才执行一次连接诊断。原生通道还需检查辅助应用程序；COM 正常不代表 DLL 已运行。

## 常见现象

| 现象 | 检查方向 |
|---|---|
| `XToolkitNotFound` | 未运行、会话不可见或连接上下文不同；先查界面和进程 |
| `XToolkitAmbiguous` | 多个可连接会话；由用户辨认处理，不自动选择或结束 |
| `XToolkitCantModify` | 模态框、导入或命令尚未结束；回界面确认当前操作 |
| `-2147221005` / 无效类字符串 | COM 注册对当前上下文不可见；核对目标安装，再采用正式注册方式 |
| `-2147221008` / `CoInitialize` | 调用线程未初始化 COM；修正线程初始化，不跨线程复用对象规避 |
| `-2147417851` / `RPC_E_SERVERFAULT` | 停止重复调用，检查界面、日志和当前命令，不自动清理服务 |
| `-2147467262` / `E_NOINTERFACE` | 包装类型、接口 IID 或 COM 对象不匹配；查类型库，连续重试无益 |
| 辅助应用程序未运行 | 核对插件版本、`protk.dat`、运行状态和 ID 缓存；旧 ID 文件不证明已运行 |
| `XToolkitInUse` | DLL 已加载或映射仍在；停止加载，不通过改名绕过 |
| `LNK1104` | 构建目标被占用或路径错误；可用独立开发输出验编译，不覆盖已加载 DLL |

## 显示和导入

`ok:true` / `shown` 只代表调用返回成功。实际窗口可能未激活，视角不合适，或导入结果只有曲面。先通过 Creo 界面确认文件、窗口和适屏；不能因当前模型属性读取失败就认定已保存文件无效。

COM 当前模型有时返回通用接口对象，后端应使用经过确认的接口包装或已知模型对象。宏命令可能排队执行，截图须等 GUI 实际完成。

中文启动优先使用用户已有入口和工作目录。英文界面或 Embedded Browser 初始化错误应记录实际错误、入口、权限、区域变量和多开情况；一次本地故障不足以证明单一根因。不要自动改全局区域设置或浏览器缓存试错。
