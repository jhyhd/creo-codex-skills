# 可选 TOOLKIT 后端开发

本仓库只分发技能与说明，不附带 C++ 后端、PTC SDK、厂商示例源码或编译产物。本页供自行持有兼容桥接源码和合法开发环境的维护者参考，不是可直接构建的后端项目。

## 前提与职责

需要匹配所用 Creo 版本的 TOOLKIT SDK、相应授权、x64 C++ 工具链和 Windows SDK。许可配置应来自用户自己的受权环境；不要提交许可文件、服务器地址或私人路径。

原实现的职责划分可供移植参考：

| 逻辑模块 | 职责 |
|---|---|
| `agent_bridge.cpp` | 初始化、ping、请求/返回值及分发边界 |
| `features.cpp` | 核心特征与调度 |
| `features_a4.inc` | 其他特征、选择过滤和尺寸修改 |
| `elem_utils.cpp` | 元素树、选择引用等通用辅助 |
| Python 原生桥 | COM 参数、应用句柄、当前模型及配方保存 |

这些文件名只描述原实现，本仓库没有对应源码。其他后端可用不同结构，但应明确工具契约和副作用。

## 逐层验收

1. **离线构建**：编译独立开发输出，检查导出符号和依赖；构建失败即停止，不解锁或测试旧 DLL。
2. **插件通路**：在用户允许的独立测试会话验证初始化、ping、输入及返回错误，明确句柄生命周期，避免孤儿 DLL。
3. **最小特征**：一次引入一个最小元素树，验证创建、再生、类型与活动状态后再加参考和选项，不在工作模型上直接试复杂树。
4. **几何持久化**：核对尺寸、实体/面组数量、体积或面积、保存及回读；通信成功不等于业务成功。
5. **批量与修改**：最后验证失败索引、部分结果、重复调用、就地修改、配方重建和备份恢复。

使用安装的 SDK 文档和样例核对 API，不将它们复制进本仓库。头文件未找到某接口只支持当前检查范围内的结论，不能替代官方产品能力说明。

## 构建与加载

DLL 在 Creo 中加载时通常无法覆盖。用独立开发构建验证编译；切换版本前让用户处理未保存内容和加载状态。原实现使用过 `protk_unlock`，此流程需要匹配的 PTC 授权和官方工具，不替代产品许可证，也不应从不明来源下载解锁工具。

加载配置和 `UserDisplay` 行为须按后端与版本验证。不反复加载同一路径，也不换名/换路径绕过 `XToolkitInUse`；不结束 `pfclscom.exe` 释放构建占用。服务器故障按[排障说明](TROUBLESHOOTING.md)保留现场。

值得保留的实现约束：

- 返回 `stage`、`pro_error` 和可读错误表，区分传输与业务成功。
- SDK 要求 `ProArray` 时使用真实分配的 `ProArray`，不用普通 C 数组冒充。
- 按面组/曲面实际类型转换，不将 surface 项传给只接收 quilt 的函数。
- 按调用线程初始化 COM，明确应用句柄、引用、数组及字符串的所有权。
- `draft`、`mirror` 安全桩返回未实现，不将路由存在当成支持证据。

发布后端前先移除静默结束进程的失败处理，为同名重建增加可审阅的备份和覆盖策略。旧实现的自动清理、宽泛重试和 `.prt*` 删除行为不应成为新后端默认模式。
