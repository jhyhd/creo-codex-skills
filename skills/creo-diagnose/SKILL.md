# Creo 连接与运行诊断

本技能面向独立部署的 Creo MCP 与 TOOLKIT 后端，不包含服务端、注册脚本或 SDK。接口名是参考后端约定，先查看安装版本的工具和日志配置。

## 收集证据

1. 保存原始错误码、错误阶段和触发操作。检查目标会话、Creo 是否响应、是否有模态弹窗；不要关闭无关模型或进程。
2. **先确认后端连接逻辑是否有自动终止进程、注册 COM 或重启等副作用。** 某些旧参考实现连接失败后会清理 `pfclscom.exe`。这类实现不应在活动会话中反复用状态接口探测；优先检查窗口、进程和日志，修正部署或采用无清理的诊断入口。
3. 对已确认无破坏性副作用的后端，按需要调用一次 `creo_status` / `creo_diagnose`，查看 `connect`、`processes`、`creo_sessions_estimate`、`com_initialized`、`thread_id`、`connect_error`、`models`。字段以实际返回为准。
4. 仅在排查原生特征通道时检查 `creo_native_status` 的 app id 与 ping；STEP 导入无需通过 TOOLKIT 状态检查。
5. 根据证据修正一个原因后再试一次。重复同一连接错误时停止自动尝试，报告保留状态和可执行的下一步。

## 常见错误

| 错误或现象 | 检查方向与处理 |
|---|---|
| `-2147221005` 类字符串无效 | 确认 ProgID、安装架构及当前用户/机器级 COM 注册可见性；仅在确认缺失后按所部署后端的安装说明修复 |
| `-2147221008` 未调用 CoInitialize | 调用线程需初始化 COM；检查后端线程处理，不能假定所有版本都已修复 |
| `XToolkitAmbiguous` | 查明多会话及目标，不自动结束多余会话 |
| `XToolkitCantModify` | 检查模态对话框、正在执行的命令或忙状态 |
| `XToolkitNotFound` | 确认 Creo 运行状态及目标会话；未运行时由既定启动方式打开 |
| 辅助应用程序未运行 | 查看 `protkdat`、插件运行状态和实际 app id，不能只信任旧缓存文件 |
| `XToolkitInUse` | DLL 已映射或句柄状态不符；停止重载，不用换名字、路径或结束通信进程来绕过占用 |
| `XToolkitCommError` / RPC 服务错误 | 记录原文，查明窗口、会话与通信状态；不要从单个错误推断根因 |
| 工具返回显示成功但窗口空白 | 检查目标模型窗口是否创建、激活和适屏，实际截图确认；COM 返回值不证明用户已看见模型 |

## 保留现场

- 不终止 `pfclscom.exe`；它可能承载正在使用的通信与插件句柄。
- 不为排障擅自关闭 Creo、丢弃未保存模型、修改注册表或全局启动设置。若确需这类操作，说明已确认的原因并按当前任务授权执行。
- 日志路径以部署配置为准，常见位置为 MCP 根目录中的 `mcp_debug.log`、TOOLKIT 根目录中的 `out/debug.log`。对外分享前移除用户路径、许可证位置和模型敏感信息。
- 区分“已证实原因”“可能原因”和“未验证修复”。汇报最小可复现触发条件、证据及下一步，不能把重启后的暂时恢复当成根因已解决。
