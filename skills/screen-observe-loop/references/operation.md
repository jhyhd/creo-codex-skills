# 采集器与闭环操作

## 前提

采集器面向 Windows 桌面和 Python。它只能读取当前可见像素：窗口被遮挡、最小化、切换桌面或锁屏时，不能把所得画面视为目标应用的可靠状态。它不会自动激活窗口，也不会绕过锁屏或显示权限。

宿主需要能够运行脚本、保留运行进程，并用 `view_image` 或同类工具查看本地 PNG。采集器不包含 OCR、目标识别、鼠标或键盘控制；这些判断与行动由 agent 使用已有工具完成。

## 参数约定

先运行 `python scripts/observe_screen.py --help` 核对安装版本。发布版本提供：

| 参数或模式 | 用途 |
|---|---|
| `--list-windows` | 枚举可见窗口标题及句柄，帮助选择观察对象 |
| `capture` | 立即采集一帧并写入输出目录 |
| `watch` | 在给定时长内周期采集，保存发生像素变化的帧 |
| `--output-dir` | 本次任务的本地输出目录 |
| `--window-title` | 将观察限制在匹配的目标窗口可见区域 |
| `--region x y width height` | 将观察限制在指定屏幕区域；坐标按采集器帮助说明解释 |
| `--interval` | 秒，默认 2，最小 0.5 |
| `--duration` | 秒，默认 30，最大 300；长任务分段观察并汇报 |
| `--stop-file` | 文件出现时停止 `watch`，用于提前结束或响应用户停止 |

优先选择唯一窗口标题。多个窗口匹配或目标不存在时先解决目标不明确的问题，不猜测窗口，也不把标题过滤失败当作扩大采集范围的理由。

`--region` 使用虚拟桌面的绝对物理像素坐标；副显示器上的 X/Y 可以为负数。`--window-title` 与 `--region` 不能同时指定；窗口观察只覆盖其当前可见的屏幕矩形，不提供被遮挡部分的后台渲染。

## 输出与新鲜度

输出包含 `latest.png`、编号帧 PNG、`latest.json` 及 `events.jsonl`。根据实际元数据读取新帧的序号、哈希、生成时间和文件路径；不要仅凭 `latest.png` 的文件名判断新鲜度。

关键判断优先读取 `latest.json` 中 `path` 对应的独立帧文件。`latest.png` 和 `latest.json` 分别更新，不应假设它们总能成对原子读取；同时检查 `target_is_foreground`、目标标题及实际遮挡情况。

`watch` 只保存变化帧，因此一段时间没有新帧可能只是画面保持不变。记录的像素变化不等于语义进展；进度动画持续变化也可能仍在同一阶段。每次作关键判断，都应实际查看对应的新图像。

## 一次完整循环

以“等待应用打开文件并确认内容可见”为例：

1. 采集并查看基线，识别当前文件名、主窗口、弹窗和内容区域。
2. 执行当前任务已授权的打开操作，再开启 30 秒短观察段。
3. 工具进程运行时，在可打断的短周期内检查新帧。发现新帧后立即看图，区别加载中、错误、空白窗口和目标内容。
4. 若出现需要选择的对话框，停止盲等；读取对话框内容，只作已授权且依据充分的选择，再截图复核。
5. 看到目标文件名及所需内容完整可见后结束采集。若只看到文件名或部分内容，继续验证尚缺条件，不提前报告完成。

提前停止示例：

```powershell
New-Item -ItemType File -Path $stopFile -Force | Out-Null
```

随后确认原进程退出。用户要求停止时，优先停止当前观察进程或触发其停止文件，不等待原定时限。停止文件仅控制采集器，不用于终止目标应用。
